# ISSUE-015: Regex Compilation Without Size Limit

## Summary
User-provided regex patterns from `keploy.yml` bypass rules are compiled without length or complexity limits. A crafted ReDoS pattern (e.g., `(a+)+b`) in the config can hang the matching engine indefinitely.

## Suggested Patch
```go
const maxRegexLen = 1024

func compileBypassRegex(pattern string) (*regexp.Regexp, error) {
    if len(pattern) > maxRegexLen {
        return nil, fmt.Errorf("bypass regex too long (%d chars, max %d)", len(pattern), maxRegexLen)
    }
    return regexp.Compile(pattern)
}
```
Pre-compile all bypass regexes at config load time in `ValidateFlags`.

# ISSUE-016: No Port Number Validation

## Summary
Port fields (`Port`, `ProxyPort`, `DNSPort`) are `uint32` but valid TCP ports are 1-65535. No validation rejects invalid values.

## Suggested Patch
Add to `ValidateFlags`:
```go
func validatePort(name string, port uint32) error {
    if port > 65535 {
        return fmt.Errorf("invalid %s port %d: must be 0-65535", name, port)
    }
    return nil
}
```

# ISSUE-021: HTTP Response Body Not Drained Before Close

## Summary
Multiple `defer resp.Body.Close()` calls without `io.Copy(io.Discard, resp.Body)` first. Go HTTP transport only reuses TCP connections when body is fully consumed.

## Suggested Patch
Create a helper:
```go
func drainAndClose(body io.ReadCloser) {
    io.Copy(io.Discard, body)
    body.Close()
}
```
Replace `defer resp.Body.Close()` with `defer drainAndClose(resp.Body)`.
